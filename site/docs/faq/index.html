FAQ

Short answers to the questions that come up most.

Can I use a private repository?

Only on a paid GitHub plan. On a free account, GitHub Pages is available for public repositories. Your site is public either way once it's published.

Does it cost anything?

Public repositories get GitHub Actions minutes at no charge, and Pages is free for them. Plans and limits change, so check GitHub's current pricing page for the details that apply to you.

How do I roll back a bad deploy?

Revert the commit and push. The workflow runs again and publishes the previous version.

git revert HEAD
git push
Can I deploy from a branch other than main?

Yes. Change the branch name under push and pull_request in .github/workflows/deploy.yml. Also allow that branch in Settings, Environments, github-pages.

Can I use a static site generator or a bundler?

Yes. The workflow only needs npm run build to put the finished site in dist/. Replace the build script with your generator's command, add an install step to the workflow if you have dependencies, and keep the output folder as dist. The tests keep working on whatever ends up there.

Can I use a custom domain?

Yes. Add a CNAME file to site/ and set the domain in Pages settings. The customization guide has the steps.

Does the site work without JavaScript?

Yes. Every page is plain HTML. The script only adds the theme button, copy buttons on code blocks, the mobile menu, the contents list beside documentation and the animation on the home page.

Where do the fonts come from?

They are stored in site/fonts/ and served with the site, so visitors don't contact a third-party font server. Both fonts are licensed under the SIL Open Font License, and the license files sit next to them.

Why is there no watch mode?

The build takes a moment and touches only a few files, so a watcher would add a dependency for little gain. Run npm start again after an edit. If you want live reload, add a tool such as a file watcher and call npm run build from it.

How do I report a problem or suggest a change?

Open an issue in the GitHub repository.
