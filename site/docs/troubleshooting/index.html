Troubleshooting

Find the symptom, then follow the fix. Most problems come down to one setting or one broken link.

The run fails at "Configure Pages"

The log shows an error that starts with Get Pages site failed. Pages isn't set up to use GitHub Actions yet.

Fix: open Settings, then Pages, and set Source to GitHub Actions. Then re-run the failed workflow from the Actions tab.

"Resource not accessible by integration"

The workflow doesn't have permission to publish. This usually means the permissions block was removed or the repository restricts workflow permissions.

Fix: keep pages: write and id-token: write in the workflow. Then check Settings, Actions, General, Workflow permissions and make sure nothing blocks the workflow from running.

Deployment blocked by environment rules

The deploy job fails and says the branch isn't allowed to deploy to the github-pages environment.

Fix: open Settings, then Environments, then github-pages. Under Deployment branches and tags, allow main, or remove the restriction.

A test fails

The Test site step lists every problem it found, one per line, each starting with the page it came from.

MessageWhat to do
broken linkThe target file doesn't exist. Check the spelling, or create the page
broken anchorThe page exists but has no element with that id. Add the id or fix the link
missing or empty <title>Give the page a title in its <head>
expected exactly one <h1>Use one top-level heading per page
image is missing alt textAdd an alt attribute. Use alt="" for purely decorative images
unexpanded placeholderA partial name is misspelled, or a placeholder was typed in a way the build doesn't recognize

Run npm run check on your machine to reproduce the failure before you push again.

The site didn't update

  • Did you push to main? Pull requests build and test but never deploy.
  • Did the run pass? A failed test or build stops the deploy job.
  • Is the old page cached? Hard-refresh with Ctrl + Shift + R. GitHub's servers can also take a minute to catch up after a deploy.

The page loads without styles

The HTML loads but the stylesheet or fonts return a 404 error. This almost always means a link starts with /. On a project page the site lives at /repo/, so /style.css points to the wrong place.

Fix: write internal links with the root placeholder, as in {{root}}style.css, instead of a leading slash. The customization guide explains how it works.

A 404 page for an address that should exist

  • Addresses are case-sensitive on GitHub Pages. /Docs/ and /docs/ are different.
  • A page at site/about/index.html is served at /about/. A file named site/about.html is served at /about.html.
  • Check that the file is inside site/. Anything outside it isn't published.

Pages is missing from Settings

On a free GitHub account, Pages is only available for public repositories. Make the repository public, or move to a plan that supports Pages on private repositories.
