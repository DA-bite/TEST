Customization

The site is a folder of HTML, one stylesheet and one small script. Change whatever you like.

Change the content

Everything you publish lives in site/. Edit the pages there, then build and test.

npm run check

Shared layout with partials

The head, header, footer and documentation menu are written once in site/partials/ and pulled into each page at build time. Change a partial and every page updates.

PartialContains
headCharset, viewport, icon, stylesheet and the theme script
headerBrand, main navigation, theme and menu buttons
footerFooter links and the site script
docs-navThe menu beside documentation pages

Placeholders

The build replaces two placeholders in every page and partial.

PlaceholderBecomes
{{root}}The relative path back to the site root: ./ on the home page, ../ one folder down, ../../ two down
{{base}}The path the site is served from, such as /my-repo. Only 404.html uses it

Write every internal link as {{root}} followed by the path, for example {{root}}docs/faq/. That keeps the site working under /repo/ and on a custom domain.

Add a page

  1. Create the file

    Make site/about/index.html. A folder with an index.html gives you a clean address, /about/.

  2. Start from this skeleton 
    <!doctype html>
<html lang="en">
<head>
  <!-- @include head -->
  <title>About - My Site</title>
  <meta name="description" content="Who we are.">
</head>
<body>
<!-- @include header -->
<main id="main">
  <div class="bar">
    <h1>About</h1>
  </div>
</main>
<!-- @include footer -->
</body>
</html>
  3. Link to it

    Add a link in site/partials/header.html. For a documentation page, add it to docs-nav.html instead and copy the layout from any page in site/docs/.

Colors and type

The design tokens sit at the top of site/style.css: --paper for the page, --surface for raised areas, --ink for text, --muted for secondary text, --line for borders and --action for links and buttons.

The dark theme repeats the same tokens twice. One copy applies when the visitor's system prefers dark. The other applies when they pick dark with the theme button. Change both so the two paths match.

Check contrast after changing colors

Body text needs a contrast ratio of at least 4.5 to 1 against its background. Check --muted and --action in both themes.

Fonts

Bricolage Grotesque and JetBrains Mono are stored in site/fonts/ with their licenses. To swap them, add your font files, update the two @font-face rules and the --font-body and --font-mono tokens, and update the preload line in partials/head.html.

Use a custom domain

  1. Add a CNAME file

    Create site/CNAME containing your domain on a single line, for example docs.example.com. The build copies it into dist/.

  2. Set the domain in GitHub

    Open Settings, then Pages, and enter the domain under Custom domain.

  3. Point your DNS at GitHub

    Follow GitHub's instructions for the type of domain you use. Turn on Enforce HTTPS once the certificate is ready.

No other change is needed. Links are relative, and the workflow reads the new path from Pages automatically.

Add your own checks

scripts/test.mjs collects problems with a small fail(message) function and exits with an error if any were reported. To add a check, loop over the pages and call fail when something is wrong. For example, to require a meta description on every page:

if (!/<meta[^>]*name=["']description["']/i.test(html)) {
  fail(`${rel}: missing meta description`);
}

Put it inside the loop that already reads each page, next to the title check.

Change the Node version

Edit node-version in .github/workflows/deploy.yml and engines in package.json. The scripts use only built-in Node modules, so any current release works.
