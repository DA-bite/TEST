What happens after you push

Four stages, in order. If one fails, the ones after it don't run.

  1. Push

    Commit your changes to main. A pull request runs the build and tests without deploying, so you can review a change before it goes live.

    git add .
git commit -m "Update the docs"
git push origin main

  2. Build

    A short Node script copies site/ to dist/, fills in the shared header and footer, and makes every path relative. There is nothing to install.

    npm run build

  3. Test

    The tests read the built pages and fail the run if something is broken. A failure here means nothing gets published.

    • Every internal link, image, stylesheet and script resolves
    • Every #anchor points to a real heading or id
    • Each page has a title, language, viewport tag and one h1
    • Images have alt text and ids are unique
    • No unexpanded placeholders are left behind

  4. Deploy

    The dist/ folder is uploaded as a Pages artifact and published with GitHub's own actions. The run summary links straight to the live site.

    https://<user>.github.io/<repo>/

Built to stay out of your way

No dependencies
Node 20 and the files in this repository. There is nothing to install and nothing to keep updated.
Works under any path
Links are relative, so the site runs at /repo/ on a project page and at the root of a custom domain.
Safe pull requests
Pull requests build and test but never deploy. Only main publishes.
Readable by default
Light and dark themes, visible keyboard focus, a skip link and support for reduced motion.
Fonts that ship with the site
Bricolage Grotesque and JetBrains Mono are served from this repository, so visitors never hit a third-party font server.
Two scripts you can read
build.mjs and test.mjs are short enough to read in one sitting and change when you need to.

What's in the repository

Your content lives in site/. Everything else is plumbing you can leave alone until you need it.
